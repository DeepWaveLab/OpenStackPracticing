# 結語:三次嘗試,才有這一朵雲

這門課從一台空白的 Azure VM 開始,到一朵能收錢、能自癒、能對稽核交代的雲結束。但它真正的起點,在課程開始之前——是[兩次沒走完的嘗試](../previous-attempts.md)。

第一次用 Juju + Charms,走了九天,核心跑得起來,卻在三個關鍵功能上被生態系卡死。第二次換 OpenStack-Helm,兩天就喊停:每個問題都要跨 K8s 和 OpenStack 兩層除錯,拆一顆雷得先拆另一顆。這兩次不是繞路——它們把地形摸熟了,第三次用 Kolla-Ansible + Magnum CAPI 走得完,是因為前面已經知道坑在哪。

所以別把這門課讀成一份「照著做就會成功」的食譜。它更像一份走通之前先走壞過的紀錄:每一章結尾那句「誠實的差距」,不是免責聲明,是它的骨架。它沒有一次假裝做到了其實沒做到的事——那份克制,比任何一個綠色勾勾都更接近真實的工程長什麼樣子。

## 接下來,往哪走

這要看你是誰。

剛入門、還被一堆陌生名詞淹沒的話,先別急著自己架一朵雲。這朵雲只是載體,你真正該帶走的是那套除錯的反射——找第一張骨牌、換個身分再問一次、先設判準再動手。帶著它,回頭把 Linux、網路、Kubernetes 的底子補紮實,比硬撐著蓋一朵自己看不懂的雲有用得多。

寫應用的你,現在多了一台 X 光機。PVC、負載平衡、代管資料庫、額度、SSO、帳單,底下到底是誰在動工,你看得見了。拿這雙眼睛回去讀你自己平台的文件,會讀出以前讀不到的東西。

同樣在做平台的人,最好的下一步是把它 fork 下來、開成多節點,去踩課程誠實列出的那幾個坑:fencing、真的 CA、全服務稽核。那些難的地方都不在 OpenStack 本身,在它接的那個外部世界——也正是最值得練的地方。

## 最後一句

這朵雲用的每個版本,幾年後都會被換掉;你為了讓它跑起來養成的判斷,不會。

而不管你是哪一種讀者,有件事這門課用它自己的三次嘗試示範過了:第一次不會成功,第二次也不一定,而走不通的那幾次不是浪費,是在替下一次摸路。

謝謝你走完這趟。現在,去蓋一朵你自己的——蓋壞了也沒關係,這門課就是這樣來的。
