    親手蓋一朵雲¶

    OpenStack 是什麼？¶

    OpenStack 是用來建置雲端基礎設施的開源軟體。 它把伺服器的運算能力、儲存空間與網路集中管理，讓使用者透過網頁或指令建立虛擬機、配置網路、掛載磁碟。把這些基礎設施提供給使用者自行取用，就是「基礎設施即服務」（Infrastructure as a Service，IaaS）。企業可以用它建立內部使用的私有雲，雲端業者也可以用它提供公有雲服務。官方介紹

    例如，你要建立一台有網路、能存資料的虛擬機。使用者只需要選擇作業系統映像檔、CPU 與記憶體規格，以及要連接的網路；雲端平台則要確認使用權限、選擇承載它的主機，並完成網路與磁碟設定。OpenStack 把這些工作分給不同服務，讓它們合作完成同一個請求。

    其中，Nova 負責虛擬機的建立與管理，Neutron 負責網路，Cinder 提供可掛載到虛擬機的持久磁碟。你會在下方看到這些服務各自的吉祥物與用途；讀到後面的章節時，可以用圖片和名稱一起辨認它們。

    這門課會帶你部署並操作這些服務。實驗從 Azure 上一台支援巢狀虛擬化的 VM 開始，也就是在這台 VM 裡再執行虛擬機。部署完成後，到了 Day 2，你會對自己的 OpenStack 環境送出建立虛擬機的指令：

    openstack server create --flavor m1.tiny --image cirros --network net1 vm-cirros

    這行指令指定虛擬機規格 m1.tiny、映像檔 cirros、網路 net1，並將新虛擬機命名為 vm-cirros。這些資源會在 Day 2 先準備好，你也會確認建立出的虛擬機能否連線。接著，課程逐步加入持久磁碟、負載平衡與 Kubernetes 叢集管理，再進入多節點維運、租戶與安全管理。

    由左至右是 Keystone、Glance、Nova、Neutron、Cinder、Octavia、Barbican 與 Magnum 的官方吉祥物。下方的服務表會沿用這些圖片，說明各自負責的工作。

    這門課適合誰、需要什麼底子

    • 平台、DevOps 與 SRE 工程師：練習部署雲端基礎設施，理解服務如何合作，以及如何追查故障。
    • 後端與應用工程師：理解虛擬機、磁碟、負載平衡與代管資料庫背後的資源管理方式。
    • 先備知識：會 Linux 命令列、SSH、IP 網段與路由即可開始。Day 6 起會使用 Kubernetes 的 Pod、Deployment 與 kubectl；不熟悉的讀者可以先看 Learn Kubernetes Basics。Day 28 起會使用 Prometheus 的查詢語言 PromQL，章節會說明查詢的用途。

    動手需要自己的 Azure 訂閱，以及各章指定的 VM、磁碟與網路資源。前段使用單機環境，後段另建獨立多節點環境；課程各章會交代實驗前提與驗證範圍。

    這朵雲能做成什麼¶

    下表把課程會操作的服務、吉祥物與用途放在一起。右側列出公有雲中用途相近的服務，方便已有使用經驗的讀者對照；它們的功能範圍與管理方式並不完全相同。

    服務 它給你什麼 AWS GCP Azure
    Keystone 身分認證與存取控制 IAM Cloud IAM Entra ID
    Glance VM 映像檔管理 AMI Images Compute Gallery
    Nova 虛擬機生命週期與運算調度 EC2 Compute Engine Virtual Machines
    Neutron 軟體定義網路:網段、路由、防火牆 VPC VPC Virtual Network
    Cinder 區塊儲存:可掛載、可搬移的持久磁碟 EBS Persistent Disk Managed Disks
    Octavia 將連線分配至多台虛擬機（負載平衡） ELB Cloud Load Balancing Load Balancer
    Barbican 金鑰、憑證與機密集中管理 Secrets Manager Secret Manager Key Vault
    Heat 用範本建立網路、虛擬機等資源（資源編排） CloudFormation Infrastructure Manager Bicep / ARM
    Magnum 代管 Kubernetes 叢集 EKS GKE AKS
    Horizon 雲資源的網頁管理介面 Console Cloud Console Portal
    物件儲存(RGW) 物件儲存：課程實作 Swift API，S3 為選讀 S3 Cloud Storage Blob Storage
    Manila 共享檔案系統 EFS Filestore Azure Files
    Designate DNS 代管 Route 53 Cloud DNS Azure DNS
    Trove 資料庫即服務 RDS Cloud SQL Azure Database
    Telemetry 用量計量；告警與擴縮接續於 Day 29 CloudWatch Cloud Monitoring Azure Monitor
    CloudKitty 依用量與費率計價 Cost Explorer Cloud Billing Cost Management
    Masakari 主機故障通知後的虛擬機恢復 (EC2 內建自動復原) (內建即時遷移) (內建服務修復)

    點服務名稱可以直接跳到對應章節。Swift 的吉祥物在這裡標示物件儲存介面；本課程實際部署的是提供 Swift API 的 Ceph RGW。Telemetry 的計量與告警分別在 Day 28、Day 29 說明。

    課程使用的部署工具¶

    Kolla-Ansible 是部署 OpenStack 的工具，將各項服務放在容器中執行，再透過自動化設定完成整合。前期嘗試過的 Juju 與 OpenStack-Helm 採用不同的部署方式；它們遇到的整合限制與選擇依據，保留在前兩次嘗試，供需要比較工具的讀者參考。

    建立 Kubernetes 叢集時，OpenStack 做了什麼？¶

    有了虛擬機與網路之後，還能在其上建立 Kubernetes 叢集，用來執行容器化應用程式。Magnum 提供叢集管理介面，本課程透過 Cluster API 將叢集需求轉成 OpenStack 資源。下圖由上往下呈現請求如何建立節點虛擬機、網路與負載平衡器。

    圖中的 Nova、Neutron 與 Octavia，就是前面服務表裡的運算、網路與負載平衡服務。Kubernetes 的節點會執行在 Nova 建立的虛擬機上，節點之間透過 Neutron 網路連線，叢集 API 則透過 Octavia 的負載平衡器存取。Day 6–8 會逐步建立並解釋這些連結。

    Cluster API 的圖示在表達什麼？¶

    Cluster API 的官方標誌是大龜馱著小龜，龜殼上有 Kubernetes 的舵輪。這張圖呼應它用 Kubernetes 管理其他 Kubernetes 叢集的做法：先有一個管理叢集，再由其中的控制器建立與管理執行應用程式的叢集。專案以這句話描述這個概念：

    "It's Kubernetes all the way down."(一路往下,全是 Kubernetes)

    管理叢集和執行應用程式的叢集各自做什麼？詳見 Day 6 · Cluster API 管理叢集
